# 报告识别与病理目录匹配 · 1.1.0-preview

本版在旧 EXE 的文字工作流基础上重新实现：穿刺/术前病理、术后大病理、免疫组化、HER2 FISH/ISH → 原文证据与人工核对 → 按阶段/受体分型检索方案目录 → 医生选定方案后进入既有剂量算术核对。全部在本机运行。

## 使用

1. 首页点击“报告识别与病理匹配”，分别粘贴同一患者、同一病灶及同一取材时点的报告文字。合计最多 40000 字。可先载入虚拟示例。
2. 点击“识别报告”，查看 ER、PR、HER2 IHC、ISH 最终结论及 Ki-67。每个字段显示报告来源和未经翻译的原文证据。
3. 逐项核对；如手工修改受体字段，填写修正依据。确认当前阶段（术前新辅助、未做新辅助的术后辅助、新辅助后的术后衔接）、绝经状态、已完成术式及淋巴结状态，勾选报告核对。低表达或不常见受体组合另需专项复核。
4. 点击“匹配方案目录”。列表是目录检索结果，不是个体化治疗建议，不按淋巴结或绝经状态自动排序、推荐或修改药物。
5. 医生选择一个条目，核对原指南适用条件和详情后填写剂量参数。原有方案/参数确认依然必需；匹配本身不触发剂量计算。

新辅助后的术后分支只展示衔接摘要，不列出整套初始辅助化疗；它不自动判断 pCR、残留病灶、治疗完成程度或应使用何种衔接药物。

## 识别边界

- 识别报告文字的明确受体结果，不识别病理切片，不诊断浸润性癌，不自动推断疾病分期或治疗指征。照片和扫描 PDF 未提供 OCR；旧版同样要求先转成文字。
- 支持简体/繁体文字、常见英文标记、全角字符及部分常见受体别名。不是对所有医院模板的完整解析器。
- ER 的明确百分数区分低表达；不把低表达自动归为三阴性。Ki-67 只展示，不据此推断 Luminal A/B 或化疗指征。
- IHC 2+ 须核对明确 ISH 最终结论；仅有 HER2/CEP17 比值、拷贝数等数值时不自动判读。IHC/ISH 不一致、多来源矛盾、待出、参考范围或不确定表述会提示核对。
- 不按文档有无自动选择治疗阶段；没有粘贴某份报告不等于检查或既往治疗不存在。
- 手工修正需要依据，仍由专业人员对原始报告负责。软件不验证核对人身份、病理质量或临床适用性。

报告原文、修正和匹配结果仅在窗口内存中；不上传、自动保存或写日志。切换语言保留原文和修正值，清除匹配结果、确认和旧剂量。修改报告会清除识别及匹配；修改核对字段会清除匹配和剂量。清空全部报告也清空身高、体重、肾功能和核对人，供切换病例使用。原文不会自动进入剂量核对单；计算 JSON 只附经核对的受体字段、阶段、目录条目及修正依据。

## 实现与来源

共享引擎：`packages/calculation-core/src/reports.mjs`；共享界面：`apps/shared-web/reports-ui.js`。`scripts/build-web.mjs` 生成浏览器引擎，EXE/APK/DMG 均内置同一份文件，不依赖云端模型。

旧 `report_logic` 和 `report_panel` 的反编译文本存在错位的条件/循环及语法缺失。本次静态反汇编核对了原文分段、字段聚合、受体分型、四项核对及目录筛选的工作流；未执行旧 EXE，也没有恢复完整的旧 Python 项目。新实现使用隔离的虚构报告测试，不能据此声称与旧程序所有行为一致。

方案数据沿用已记录来源页码的 2026 CSCO 目录。受体边界另外核对了 [ASCO/CAP ER/PgR 2020 指南官方说明](https://www.cap.org/cap-guidelines/estrogen-and-progesterone-receptor-testing-in-breast-cancer-guideline-update/)和 [ASCO/CAP HER2 2023 官方说明](https://www.cap.org/cap-guidelines/her2-testing-in-breast-cancer-2023-guideline-update/)。软件的保守冲突阻断不替代病理实验室的正式判读。目录、翻译和识别逻辑仍未经独立临床验证。
